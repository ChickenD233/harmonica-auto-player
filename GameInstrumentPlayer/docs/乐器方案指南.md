# 乐器方案指南

这份文档说明方案的结构，以及怎么为一款新游戏做一套方案。

## 为什么要有方案

不同游戏的乐器界面不一样，但规律基本一致：把主键盘区当成琴键。

差异只有三处：

1. **几行**。一行 = 一个八度。常见 1 到 3 行。
2. **每行哪些键**。常见 Z-M、A-J、Q-U。
3. **半音怎么按**。有的加修饰键，有的换行，有的干脆没有半音。

程序把这三处写成数据，就是「方案」。程序本身不认识任何游戏。

## 观察到的乐器布局

以下是公开资料里常见的乐器演奏布局规律，用来支撑内置方案的选择。
方案名只写键位和音域，不绑定具体游戏。

| 布局 | 键位 | 音域 | 半音 | 例子 |
|---|---|---|---|---|
| 三行 21 键 | Z-M / A-J / Q-U | 约 2 个八度 + 7 度 | 加修饰键 | 多数带半音的琴类乐器 |
| 三行 21 键 | Z-M / A-J / Q-U | 约 2 个八度 + 7 度 | 没有半音 | 只有自然音的竖琴类乐器 |
| 两行 15 键 | Z-M / Q-U | 约 1 个八度 + 7 度 | 加修饰键 | 小型琴 |
| 单行 7 键 | Z-M | 1 个八度 | 没有半音 | 简易乐器 |

三行布局里，低行与高行常常是同一套音级位移一个八度。

## 方案字段

| 字段 | 含义 | 默认 |
|---|---|---|
| `Name` | 界面显示名 | 新方案 |
| `Description` | 说明：对应哪些游戏、怎么用 | 空 |
| `NotesPerRow` | 每行几个音 | 7 |
| `NoteOffsets` | 每个琴键比行首高几个半音 | 0 2 4 5 7 9 11 |
| `BasePitch` | 第一行第一个琴键的 MIDI 音高。C4 = 60 | 60 |
| `AutoOctaveRange` | 自动选八度时最多上下移几个八度 | 1 |
| `Rows` | 行列表。每行有 `OctaveOffset` 与 `Keys` | 三行 Z-M / A-J / Q-U |
| `SharpMode` | 升半音方式 | 按修饰键 |
| `SharpModifier` | 修饰键 | key:LeftShift |
| `SharpRowOffset` | 换行方式时，换到哪一行 | 1 |
| `OutputMethod` | 输出方式 | keyboard-scancode |
| `HoldMs` | 一个键最少按多久 | 40 |
| `RetriggerMs` | 同一个键两次按下的最小间隔 | 45 |
| `ModLeadMs` | 修饰键比琴键早按多久 | 40 |
| `ReleaseGapMs` | 松前一个键到按后一个键的间隔 | 40 |
| `FrameMs` | 游戏采样一帧的估计毫秒 | 17 |

`Keys` 里每一项的写法：

| 写法 | 含义 |
|---|---|
| `key:Z` | 键盘 Z。也可以只写 `Z` |
| `key:LeftShift` | 命名键。支持 LeftShift、RightShift、LeftCtrl、RightCtrl、LeftAlt、RightAlt、Space、Tab、Enter、CapsLock |
| `mouse:left` | 鼠标左键。也支持 `mouse:middle`、`mouse:right`、`mouse:x1`、`mouse:x2` |

`Keys` 的长度可以小于 `NoteOffsets`。这时超出这一行键数的音会归到最后一个键。

## 升半音方式怎么选

| 方式 | 判断方法 |
|---|---|
| 同时按修饰键 | 在游戏里按住 Shift 再按琴键，音会升半音 |
| 换到相邻八度行 | 半音不在本行，而在另一行 |
| 自动降到最近的音级 | 乐器只有自然音。程序把 #do 当成 do 演奏 |
| 跳过这个音 | 乐器只有自然音，而且你不想听到走音 |

「自动降到最近的音级」会在界面上计入「已调音」的数量，方便你判断走音多不多。

## 时序怎么调

游戏按帧读按键。两个键的间隔短于一帧，会被折进同一帧，结果漏音或粘连。

调整顺序：

1. 先确认「游戏帧长」。60fps 填 17，30fps 填 33。
2. 漏音、音高错 → 加大「修饰键提前」。
3. 两音粘连 → 加大「同键重触发」和「抬起→按下」。
4. 极快的段落缺音 → 加大「按住最短」。

改完点「试按键」验证。还不行就把「输入兼容」选成「稳健」，它按 2 倍余量算。

## 做一套新方案的步骤

1. 在游戏里打开乐器，截图琴键界面。
2. 数一行有几个键，记下最低音。
3. 打开方案编辑器，点「新建」。
4. 填「每行音数」和「基准音高」。
5. 按截图改每个格子。
6. 选「升半音」方式。
7. 点「试按键」，切到游戏听或看。
8. 点「保存方案」。
9. 点「导出…」把 JSON 分享给别人。

## 方案文件位置

```
%LOCALAPPDATA%\GameInstrumentPlayer\profiles\
```

一个方案一个 JSON 文件。文件名取自方案的布局指纹，所以按键位内容相同的方案不会重复。

删除用户方案：在方案编辑器里点「删除方案」。内置方案不能删。

## 检查方案是否合法

程序在保存前校验：

- 至少要有一行，每行至少一个键
- 每行的键数不能多于音级表
- 不能有空琴键
- 不能有两行是同一个八度
- 「按修饰键」方式必须指定修饰键

不合法时「保存方案」按钮变灰，并显示原因。

## 用代码验证

`maptest` 测试台会检查内置方案是否自洽，以及四种升半音方式的行为：

```bash
dotnet run -c Release --project .tools/maptest
```

加一套内置方案后，这个测试会自动覆盖它。
