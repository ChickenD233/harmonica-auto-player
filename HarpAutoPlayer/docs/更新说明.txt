口琴自动演奏器 v2.0.4

【本版】
修复：**输入法自检仍然误报（中文微软拼音 + Shift 切英文）。**

2.0.3 改了判定逻辑，但读状态的位判断写错了：
IME_CMODE_ALPHANUMERIC 这个常量本身就是 0x0000，
写 `(conversion & IME_CMODE_ALPHANUMERIC) == IME_CMODE_ALPHANUMERIC` 永远为真，
于是"中文还是英文"根本没被判过。

正确的判据是 IME_CMODE_NATIVE 位：
微软拼音中文态读出来是 0x0401（带 NATIVE 位），英文态是 0x0000。

同时换了一个更可靠的读取来源：**默认输入法窗口**（ImmGetDefaultIMEWnd）。
直接问游戏窗口往往读不到（它不一定处理 WM_IME_CONTROL），
而系统为这个窗口建的输入法窗口能如实回答开关与转换模式。
实测：前台窗口回 0 / 0x0000（读不到），默认输入法窗口回 开=1 / 0x0401（中文态）。

判定表：

| 默认输入法窗口状态 | 结果 |
|---|---|
| 输入法关着 | 通过 |
| 开 + 0x0000（英文/半角） | 通过，显示「英文输入状态，按键直达」 |
| 开 + 0x0401（中文） | 不通过，提示按 Shift 切英文 |
| 开 + 全角/片假名（0x0411 / 0x0419 / 0x0409 / 0x0419） | 不通过 |
| 读不到 | 只提醒，不报错 |

读不到时改成"提醒"（灰点）而不是"不通过"（红叉）：误报不通过会拦住本来能用的配置。

验证：
- 判定用例全通过，含 IME 窗口中文态 0x0401 / 英文态 0x0000 / 全角假名 / 关着 /
  全读不到等分支，以及简中繁中日文韩文 × 各种开关组合。
- 本机实测：简体中文布局 + 输入法中文态 → 正确判为不通过（提示按 Shift）；
  切到英文态读数为 0x0000 → 正确判为通过。
